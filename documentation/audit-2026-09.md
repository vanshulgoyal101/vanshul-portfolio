publishing scripts, tests, deployment workflow, and database integration/schema.

verification; repository tests are not proof of their deployed configuration.

needed for the local audit. Ranking first for arbitrary searches is neither a

## Follow-up: visibility and animation lifecycle

The follow-up to the project-image intro leak reviewed boot, custom cursor,
navigation scroll locking and deferred background lifecycle paths. These are UI
correctness and resource-use defects, not demonstrated security exploits.

- Native cursor suppression started before a custom pointer was visible, including
  inside the hidden boot content. Mounting after boot and tying suppression to
  rendered visibility preserves the native pointer until the replacement is ready.
- Queued mouse frames could restore the cursor after pointer leave. Leave/blur
  now cancel pending frames; preference changes discard stale visibility.
- Hover handling assumed every event target implemented `closest()`. The new
  tests exposed an unhandled non-element target; an Element guard fixes it.
- Interactive background initialization drew while hidden and visibility events
  could queue parallel render loops. Visibility-aware single-frame scheduling
  prevents both, and hidden tabs no longer spawn new particles.
- Eight new deterministic unit tests cover pointer handoff, leave/blur races,
  preferences, hidden mounting, repeated visibility events and cleanup. Thirteen
  applicable integration checks pass, including boot, loaded images, pointer
  recovery, reduced motion and footer preferences (one touch-specific skip).

The navigation scroll-lock effect already restores its prior value and removes
its keyboard listener on cleanup; no change was justified in that path. This
focused follow-up is not a claim of exhaustive browser or security coverage.
